# activity_tracker_STM32

Трекер фізичної активності на STM32: плата читає акселерометр і гіроскоп (6 каналів)
і класифікує активність нейромережею безпосередньо на мікроконтролері.

Розпізнавані класи: `Lying`, `Stationary`, `Walking`, `Running`, `Stairs`.

Модель навчається на власному датасеті — див. `har-dataset/` (RealWorld HAR, позиція
`upperarm`). Формат даних на платі й у датасеті описують одні й ті самі константи
з `Core/Inc/har_model_config.h`, який **генерується** з датасету:
`python scripts/export_firmware_constants.py` у `har-dataset/`.

Платформа — B-U585I-IOT02A (STM32U585AIIxQ).

## Прошивка і дані з датчика

Плата читає акселерометр і гіроскоп ISM330DHCX по I2C, фільтрує потік і збирає вікна у форматі, який очікує модель. Вивід у ПК іде через UART (ST-LINK Virtual COM Port).

| Параметр | Значення |
|---|---|
| Датчик | ISM330DHCX, I2C2, адреса 0x6B (перевірка через WHO_AM_I) |
| Режим | ODR **104 Гц** для обох датчиків, ±4 g, ±2000 °/с, читання за сигналом data-ready |
| Формат виводу | `timestamp_ms,ax,ay,az,gx,gy,gz` (7 колонок) |
| Одиниці | акселерометр у **g**, гіроскоп у **°/с**; гравітація лишається в сигналі |
| Канал | USART1, 115200 8N1; рядок CSV іде одним `HAL_UART_Transmit` |
| Препроцесинг | ФНЧ 25 Гц (Баттерворт 4-го порядку) + вікно 208 × 6 з кроком 104 — `Core/Src/har_preproc.c` |
| Втрачені відліки | до 0.5 с добиваються інтерполяцією, більший провал рве вікно — правило те саме, що в датасеті |
| Контроль роботи | раз на 5 с: `# rate=<Гц> windows=<N> missed=<N>`; `HAR_STREAM_CSV 0` вимикає потік CSV, коли працює інференс |

Запис потоку в CSV: `python tools/log.py COM3 <клас> <людина>` (потрібен `pip install pyserial`, зупинка Ctrl+C). Файли потрапляють у `data/`.

| Документ | Про що |
|---|---|
| `firmware/activity_tracker_fw/` | Проєкт STM32CubeMX/CubeIDE (код датчика в `Core/Src/main.c`, драйвер `ism330dhcx_reg.*`) |
| `tools/log.py` | Запис потоку з COM-порту в CSV |
| `data/` | Записи з датчика (історія форматів: mg 7 колонок → м/с² 4 колонки → **g і °/с, 7 колонок**) |
| `Core/Src/har_preproc.c` | ФНЧ + накопичення вікна + нормалізація; збирається і тестується на ПК |
| `Core/Src/har_model.c` | Інференс: єдина точка виклику моделі; поки `HAR_MODEL_DEPLOYED 0` — порожній слот під мережу Cube.AI |
| `Core/Inc/har_model_config.h` | **Згенерований** з датасету: частота, вікно, класи, коефіцієнти ФНЧ, mean/std |

**Збірка:** STM32CubeIDE → Import → Existing Projects into Workspace → `firmware/activity_tracker_fw` (без Copy), Build, Run. Версія пакета STM32Cube_FW_U5_V1.9.0.

**Правила роботи з `.ioc`:** редагує один учасник за раз, свій код пишемо лише між `USER CODE BEGIN/END`, перед регенерацією робимо коміт.

**Статус:** датчик, UART і запис працюють на платі. Прошивку переведено на 104 Гц,
6 каналів, одиниці g/°/с, ФНЧ 25 Гц і буфер 208 × 6. Шар інференсу підключений:
готове вікно йде в `har_model_predict()`, результат друкується окремим рядком
`# pred t=<мс> class=<клас> p=<імовірність>` (з `#` на початку, тож `tools/log.py`
його пропускає і потік лишається придатним для збору CSV).

Лишилось одне: натренувати модель на датасеті 104 Гц, згенерувати мережу через
STM32Cube.AI, покласти `network.*` у проєкт і поставити `HAR_MODEL_DEPLOYED 1`
у `Core/Inc/har_model.h`. Доки там `0`, прошивка збирається і працює повністю,
лише без класифікації. Окремо лишається перевірка фактичної частоти на платі.

> ⚠️ При 104 Гц рядок CSV займає ~60 % пропускної здатності 115200 бод. Якщо в лозі
> з'являються рядки `# missed`, підняти швидкість UART до 921600 (і в `tools/log.py`).

## ML-частина

Використовується готова модель `st_ign` (варіант `st_ign_wl_24`) з офіційного
[STM32 AI Model Zoo](https://github.com/STMicroelectronics/stm32ai-modelzoo) — власна модель
не навчалася. Проведено офіційну оцінку: **91.78%** на публічному датасеті WISDM і **88.83%**
на demo-семплі `mobility_v1`. Визначено всі параметри збору даних, потрібні прошивці.
